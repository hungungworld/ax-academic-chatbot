# KITA 무역 AX마스터 학사규정 문의 챗봇

KITA 무역아카데미 'AX마스터' 교육생이 학사관리규정을 물어보면 챗봇이 바로 답하고,
개인 사정이나 담당자 판단이 필요한 문의는 담당자에게 접수·연결하는 챗봇입니다.
RAG(규정 검색 후 답변) + LangChain + LangGraph로 만들고, 유료 API 없이 무료로 운영합니다.
반복 문의에 답하는 운영담당자의 시간을 줄이는 것이 목적입니다.

> 상태: 4~6단계(답변 흐름, 채팅 화면, 접수·알림·담당자 화면) 구현 완료. 남은 일: Neon DB 연결, 담당자 비밀번호 설정, GitHub·Vercel 배포.

## 어떻게 동작하나

학생이 질문하면 챗봇이 질문을 세 갈래로 나눕니다.

| 분류 | 예시 | 챗봇 동작 |
|---|---|---|
| ① 규정에 명시됨 | "지각 기준이 뭐예요?", "병가 증빙은?", "수료 요건은?" | 바로 답하고 근거 조항(제N조)을 붙입니다. |
| ② 개인 사정, 담당자 판단 필요 | "제 경우 공결 되나요?", "성적 이의 제기하고 싶어요" | 규정 기준만 안내하고 담당자에게 접수합니다. 승인 여부는 말하지 않습니다. |
| ③ 규정에 없음, 범위 밖 | 규정에 없는 질문 | 지어내지 않고 담당자 연락처를 안내합니다. |

규정에서 근거를 찾지 못하면 답하지 않고 ② 또는 ③으로 보냅니다.
환불액 같은 계산은 모델이 아니라 코드가 제25조 공식으로 직접 계산합니다.

### 확정된 규정 해석

- **지각 벌점 (제13조 표)**: 09:51~10:00 입실은 "경미한 지각" 2점, 10:01 이후는 "지각" 5점입니다. (운영담당자 확인)
- **경조사 공결 (제7조)**: 규정은 "본인 직계존비속"이지만 예외가 있고 개별 판단합니다. 사망 관련 증빙서류를 받아올 수 있는 경우 등은 인정합니다. 챗봇은 확정하지 않고 담당자에게 접수합니다.
- **전시회 공결 (제7조)**: 규정은 "COEX 내 일반 전시회 인정불가"이지만, 진로·직무·산업에 도움이 되고 인사이트가 담긴 보고서를 쓰면 인정하는 경우가 있습니다. 챗봇은 확정하지 않고 담당자에게 접수합니다.
- **퇴교 (제14조 2항 가목)**: 출결 벌점이 **30점을 초과**하면 퇴교 대상입니다. 이 기준이 우선 적용되므로, 종합 점수가 -100점에 이르기 전에 먼저 퇴교될 수 있습니다. 정확히 30점은 퇴교 대상은 아니지만, 출결 벌점이 30점에 도달하면(30점 포함) 운영진과의 면담이 필수입니다. 퇴교는 자동이 아니라 면담을 거치며 최종 결정은 운영진이 합니다. (운영담당자 확인)
- **구두 허락**: 운영진이 구두로 허락했다는 학생의 주장은 예외사항이므로 담당자에게 문의해 처리합니다. 챗봇은 접수만 합니다. (운영담당자 확인)

## 기술 스택

| 항목 | 선택 |
|---|---|
| 언어 / 프레임워크 | TypeScript + Next.js |
| 배포 | Vercel (GitHub 연결 자동 배포) |
| RAG 부품 | LangChain (JS): 불러오기 · 자르기 · 임베딩 · 벡터 저장소(`MemoryVectorStore`, `@langchain/classic`) · 검색기(`asRetriever`) |
| 모델 · 임베딩 | Google Gemini 무료 API (`@langchain/google-genai`) |
| AI 흐름 | LangGraph (JS): 분류 → 검색 → 답변 또는 접수 |
| 검색 | 규정을 조 단위로 나눠 미리 임베딩해 파일로 저장, 서버가 켜질 때 메모리 벡터 저장소에 채워 검색 |
| DB | Neon (Postgres), 담당자 접수 내용 저장 |
| 담당자 알림 | 이메일 (Gmail SMTP + nodemailer, Gmail 앱 비밀번호 사용) |
| 담당자 화면 | 비밀번호 보호된 접수 목록 페이지 |

## 현재 상태

**있는 것**
- 규정 원문 정리: `rules_with_tables.md` (표 구조 유지, 원본 대비 누락 0줄 확인)
- 규정을 조 단위 42조각으로 나눈 `data/rules-chunks.json`
- Gemini 임베딩 색인 `data/rules-index.json` (`gemini-embedding-001`, 3072차원). 시험 검색에서 지각→제5조, 병가→제7조, 환불→제25조 등 맞는 조항이 1순위로 나옴
- 환불 계산(`lib/refund.ts`, 제25조 공식), 검색(`lib/retrieve.ts`), 질문 조각 나누기(`lib/chunk-rules.ts`), 담당자 연락처(`lib/contacts.ts`), 사용량 제한(`lib/limits.ts`), 공용 타입(`lib/types.ts`)
- 테스트 9개 통과, 타입 검사 통과
- 디자인 규칙(`DESIGN.md`)과 화면 시안(`preview/`)

**없는 것**
- 챗 화면과 서버 API (`app/` 폴더가 비어 있어 `npm run dev`는 아직 동작하지 않음)
- 질문 분류·답변 흐름 (LangGraph)
- 알림 메일, 담당자 접수 목록 페이지

### 색인이란?

챗봇이 질문과 비슷한 조항을 빠르게 찾으려면, 규정의 각 조항을 미리 "뜻을 나타내는 숫자 목록"으로 바꿔 파일에 저장해 두어야 합니다. 이 작업이 색인(임베딩 색인) 만들기이고, 결과 파일이 `data/rules-index.json`입니다. 책 뒤의 찾아보기와 비슷합니다.

- 질문이 들어오면 질문도 같은 방식으로 숫자로 바꿔, 숫자가 가장 비슷한 조항을 찾습니다.
- 규정 내용이나 임베딩 모델 이름이 바뀌면 색인을 다시 만들어야 합니다. 모델 이름이 색인과 다르면 검색이 안내 메시지를 냅니다.

## 환경변수

`.env.example`을 `.env`로 복사한 뒤 값을 채웁니다. `.env`는 저장소에 올리지 않습니다. 배포(Vercel)에서는 Project Settings > Environment Variables에 같은 이름으로 넣습니다.

| 이름 | 설명 |
|---|---|
| `GOOGLE_API_KEY` | Google AI Studio에서 발급한 Gemini API 키 (무료) |
| `GEMINI_MODEL` | 답변에 쓸 모델. 사용 중: `gemini-3.5-flash` (`gemini-2.5-flash`와 `gemini-2.5-flash-lite`는 이 키에서 "더 이상 제공되지 않음"으로 실패함) |
| `GEMINI_FALLBACK_MODEL` | 기본 모델이 바쁠 때(503) 대신 쓸 예비 모델, 쉼표로 여러 개 (선택). 사용 중: `gemini-3.5-flash-lite,gemini-3.1-flash-lite` |
| `GEMINI_EMBEDDING_MODEL` | 규정 검색용 임베딩 모델. 사용 중: `gemini-embedding-001` (바꾸면 색인을 다시 만들어야 함) |
| `DATABASE_URL` | Neon 연결 문자열 |
| `GMAIL_USER` | 알림을 보낼 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | 그 계정의 Gmail 앱 비밀번호 (일반 로그인 비밀번호가 아님. Google 계정에서 2단계 인증을 켠 뒤 발급) |
| `NOTIFY_TO` | 알림을 받을 담당자 이메일 (여러 명이면 쉼표로 구분) |
| `ADMIN_PASSWORD` | 담당자 접수 목록 페이지(`/admin`) 비밀번호 |
| `SESSION_SECRET` | 담당자 로그인 쿠키 서명용 임의 문자열 (32자 이상 권장) |

## 개발 단계

1. ✅ 규정 정리: 원문 정리, 조 단위 조각 나누기, 퇴교 기준 확정 (위 "확정된 규정 해석")
   - 남음: 그 밖에 규정 안에서 서로 어긋나는 부분이 더 있는지 점검
2. ✅ 검증용 질문 30개와 정답(분류 ①②③ 포함): `검증질문.md` 확정 (운영담당자 확인 요청 6건 모두 반영)
3. ✅ 색인 만들기 (Gemini 기준 완료). 규정이 바뀔 때마다 다시 만든다.
4. ✅ 분류 → 검색 → 답변/접수 흐름 (`lib/graph.ts`). 검증질문으로 확인
5. ✅ 학생용 채팅 화면 (모바일 우선, 반응형). 답변은 핵심 한 줄 → 번호 목록 → 참고 상자
6. ✅ 접수 저장(Neon), 알림 메일, 담당자 접수 목록 페이지(`/admin`). 남음: `DATABASE_URL`·`ADMIN_PASSWORD`·`SESSION_SECRET` 설정 후 `npm run db:init`
7. ⬜ GitHub에 올려 Vercel에 배포하고 BAND에 링크 공지

현재 위치: 6단계까지 구현. 다음은 환경변수 설정과 7단계(배포).

## 주의사항

- 학생이 이름이나 성적 같은 개인정보를 입력하지 않도록 화면에 안내합니다.
- 접수에는 필요한 정보(기수, 이름, 연락처, 내용)만 받습니다.
- 알림 메일은 운영담당자의 Gmail 계정으로만 발송합니다. 학생은 Gmail 키나 비밀번호를 입력하지 않으며, 계정 정보는 서버 환경변수에만 둡니다.
- 비밀 값(`.env`)은 저장소에 올리지 않고, 서버 코드에서만 읽습니다.
- 공개 링크이므로 질문 길이와 사용량에 상한을 둡니다. Gemini 무료 등급은 사용 한도가 있고 입력 내용이 서비스 개선에 쓰일 수 있습니다.
- LangChain · LangGraph 패키지 이름과 import는 설치 후 실제로 확인한 뒤 사용합니다.
- 챗봇은 규정 판단을 대신하지 않습니다. 개인별 승인·불승인은 담당자가 결정합니다.

## 담당자 문의

규정에 없는 내용이나 개인 사정은 학사규정 안내 문서의 교육 담당자 연락처를 이용합니다.
